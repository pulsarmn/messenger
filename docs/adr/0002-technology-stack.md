# ADR-0002: Выбор технологического стека

## Статус
Принято (2026-07-27)

## Контекст
Необходимо выбрать стек технологий, который будет использоваться для разработки проекта.

## Решение
Я решил использовать следующие инструменты:

- Java 25 - основной язык для разработки
- Spring Boot - основной фреймворк
- Hibernate/Spring Data JPA - ORM для работы с БД
- Liquibase - миграции БД
- PostgreSQL - основная БД
- Redis - кэширование
- JUnit 5, Mockito, AssertJ, Spring Test, TestContainers - инструменты для тестирования
- Git - система контроля версий
- Docker/Docker Compose - контейнеризация для локальной разработки и развёртывания
- Prometheus, Grafana - для сбора метрик и логов
- SpringDoc OpenAPI - Swagger документация

## Последствия
+ Современный стек
+ Быстрота и простота разработки
- Зависимость от экосистемы Spring
- Тяжеловесные jar-ники

## Альтернативы
В качестве основного фреймворка можно было выбрать например **Quarkus** или **Micronaut**, но **Spring** сейчас является стандартом де-факто, поэтому пока что нет особой выгоды переходить на экосистему других фреймворков. В будущем можно будет переписать критичные сценарии на другом фреймворке в целях оптимизации.
Также можно было бы вообще не использовать фреймворки, а писать всё с нуля, но даже создание MVP скорее всего заняло бы больше года.
