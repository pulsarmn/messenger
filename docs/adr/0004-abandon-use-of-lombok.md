# ADR-0004: Отказ от использования библиотеки Lombok

## Статус
Принято (2026-07-29)

## Контекст
Java довольно многословный язык и очень часто приходится писать много шаблонного кода. Нужно решить, использовать ли библиотеку Lombok для генерации шаблонного кода или же генерировать его вручную(например, с помощью IDE).

## Решение
Я решил отказаться от использования библиотеки Lombok по нескольким причинам:
1. **Однообразие**. Либо я использую Lombok везде, либо нигде. Я не хочу, чтобы часть кода его использовала, а часть нет. Это нужно контролировать, а на это нет времени.
2. **Явный код**. Заходя в исходный код, я точно вижу что есть в классе, а на анализ аннотаций Lombok уходит больше времени. К тому же данный код проще отлаживать.
3. **Проблемы**. При использовании сложных моделей(например, наследование), у Lombok могут возникать неожиданные проблемы, которые ты не увидишь в исходном коде. Поэтому проще написать этот код руками или сгенерировать с помощью IDE. Также заезженная тема с аннотацией @Data, которая может приводить к ошибкам, если неправильно её использовать в классах сущностей.
4. **Зависимость**. Lombok - это лишняя зависимость. Я предпочитаю максимально сокращать кол-во зависимостей
5. **Records**. К тому же, в некоторых сценариях record-классы могут полностью заменить собой аннотации Lombok.

## Последствия
+ Явный код
+ Отсутствие лишней зависимости
+ Простая отладка
- Придётся писать шаблонный код самостоятельно(либо генерировать с помощью IDE)

## Альтернативы
Тут в целом только одна альтернатива - использовать Lombok.
