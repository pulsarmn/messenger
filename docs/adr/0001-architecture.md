# ADR-0001: Выбор монолитной архитектуры на старте проекта

## Статус
Принято (2026-07-27)

## Контекст
Я приступаю к разработке мессенджера с нуля в команде, состоящей из 1 человека. Необходимо как можно быстрее реализовать MVP версию. Использование микросервисной архитектуры на начальном этапе приведёт к высоким инфраструктурным затратам и трате времени без получения ощутимой пользы.

## Решение
Я начинаю разработку с единого монолитного приложения, с чётким разделением структуры, чтобы в последующем можно было без боли перейти на модульный монолит, а в конечном итоге на микросервисную архитектуру.

## Последствия
+ Быстрота разработки
+ Простая отладка, тестирование и развёртывание
+ Единая БД
- В будущем нужно будет провести глобальный рефакторинг, чтобы разделить систему

## Альтернативы
Да, можно начать и с микросервисов, но ты погрязнешь в инфраструктурных задачах, так и не написав ни строчки кода. Поэтому этот вариант отпадает.
