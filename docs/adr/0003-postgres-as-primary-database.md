# ADR-0003: Выбор Postgres как основной БД на этапе MVP

## Статус
Принято (2026-07-27)

## Контекст
Нужно определиться, как хранить данные, и в частности, как хранить данные сообщений.

## Решение
На этапе разработки MVP я решил использовать **PostgreSQL** в качестве основного хранилища как данных пользователей, так и сообщений.
Основная причина такого выбора заключается в сложности проектирования всех запросов к **Cassandra** на начальном этапе, особенно когда знаешь Cassandra на среднем уровне :).

## Последствия
+ Быстрота и простота разработки
+ Простая работа с транзакциями(ACID гарантии на месте)
- При огромных нагрузках потребуется вертикальное масштабирование, либо партиционирование/шардирование.
- В будущем нужно будет мигрировать с PostgreSQL на Cassandra

## Альтернативы
На данный момент есть 3 варианта:
1. **Apache Cassandra** - распределённая NoSQL БД. Подходит под высокие нагрузки записи и хорошо масштабируется.
2. **ScyllaDB** - по факту та же Cassandra, только более производительная, так как написана на **C++** и из-за множества оптимизаций.
3. **PostgreSQL** - реляционная SQL БД с **ACID** гарантиями.

Почему я выбрал PostgreSQL - описал выше.
